# Decide

## Core move

Commit to a direction with the right amount of comparison.

A decision is not only a ranking. It is a commitment under constraints, uncertainty, values, timing, and cost of reversal.

## Fast path

For most ordinary decisions:

1. Identify the dominant criterion.
2. Pick the option that best satisfies it without violating hard constraints.
3. State the main tradeoff.
4. State what would change the recommendation, if relevant.

Do not produce a balanced comparison when one option is clearly better for the stated goal.

## Deep path

Use deeper comparison only when the choice is high-stakes, irreversible, expensive, ambiguous, or value-laden. For these decisions, switch to the full `evaluate` methodology to systematically weigh criteria and rigorously assess options before committing.

When navigating the deep path, ask:

- What objective is being optimized?
- What constraints cannot be violated?
- Which options are real?
- What uncertainty matters most?
- What is reversible?
- What is the cost of waiting?
- What would a bad outcome look like?
- What small action would produce useful information?

## Useful moves

- Remove dominated options.
- Choose a safe-to-try experiment when evidence is weak.
- Choose a robust option when uncertainty cannot be reduced cheaply.
- Preserve optionality when the future is unclear.
- Commit when more analysis will not change the action.

## Failure checks

Watch for:

- hiding value judgments inside technical language
- comparing every option on every criterion
- treating all uncertainty as equally important
- choosing the most elaborate option because it sounds thoughtful
- refusing to commit when the user needs a recommendation
- committing when a cheap check would change the choice

## Done when

The recommendation or decision rule, main tradeoff, and confidence or change condition are clear.

Carry forward only what the user needs to act or choose.
