# Synthesize

## Core move

Turn parts into a coherent whole.

Synthesis is not listing, summarizing, or averaging. It integrates candidates, evidence, criteria, tensions, and uncertainty into a structure that can be understood or acted on.

## Build the synthesis

Ask only what matters:

- What is the central through-line?
- Which pieces support it?
- Which pieces contradict or limit it?
- Which distinctions must remain visible?
- What can be merged, subordinated, or dropped?
- What organizing structure makes the result easier to use?

Useful structures:

- Claim -> evidence -> implication.
- Problem -> mechanism -> intervention.
- Options -> criterion -> tradeoff -> recommendation.
- Pattern -> exceptions -> boundary conditions.
- Tension -> synthesis -> remaining uncertainty.
- Parts -> relationship -> whole.

## Useful moves

- Cluster related points before judging them.
- Name the governing pattern.
- Separate signal from noise.
- Preserve the strongest minority insight.
- Reconcile contradictions when possible; surface them when not.
- Convert a list into a hierarchy.
- Compress repeated points into one sharper claim.
- Keep the distinction that would matter to a decision, diagnosis, or design.
- Carry uncertainty forward instead of hiding it in smooth prose.

## Failure checks

Watch for:

- listing instead of integrating
- averaging incompatible claims
- flattening a real tension to sound decisive
- preserving every detail because deletion feels unsafe
- deleting the one exception that changes the conclusion
- confusing synthesis with final presentation polish
- producing a conclusion that no longer follows from the parts

## Done when

The answer has an organizing structure: one through-line, model, recommendation, or integrated account that preserves the distinctions and uncertainty that still matter.

Carry forward only the synthesized structure, the key tension or limitation, and any uncertainty that should remain visible.
